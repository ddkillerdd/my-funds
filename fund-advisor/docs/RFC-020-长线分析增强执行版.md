## 2. 架构（分析⇄自适应⇄总资金⇄实际操作）

```
用户在前端填"总资金"(可变) → 存 config → 分析时动态读取
        ↓
13:30 分析一次算完:
  ├─ 历史净值 → 长期趋势/regime
  ├─ 实时指数(当日) → 短线信号(execution_advice)
  ├─ 自适应 get_active_config → target_vol/friction_band(生效参数)
  ├─ 总资金+current_mv → 计算 target_weight & action_amount
  └─ 输出 trade_actions(操作+金额+择时+参数来源)
        ↓
14:30 邮件推送 → 前端展示记录
        ↓
用户实际操作(可能≠建议) → trade_execution 记录 → 校准后续分析
```

## 3. 三块增强 + 一个修复（详细执行）

### 块 A：前端"操作建议"卡片（Phase 1, 主交付）

**数据已就绪**（后端已返回），只需前端渲染。AnalysisView.vue 新增卡片，每只基金一行：

```
┌─────────────────────────────────────────┐
│ 📊 操作建议 (基于当前生效总资金 ¥10,000)      │
│ 161725 招商白酒  → 建议【加仓】 ¥1,200       │
│   目标仓位 30% → 当前 22%  (+8pp)          │
│   短线: 今日超跌(-2.1%) → 今日可执行         │
│   参数来源: 自适应已确认(LOW风险)            │
│ 588760 科创ETF  → 建议【持有】              │
│   目标仓位 25% → 当前 25%  (0pp)           │
└─────────────────────────────────────────┘
```

- 渲染字段：`suggestion_label`、`action_amount`、`target_weight_pct`、`mv_ratio`(当前)、`suggestion`(动作)
- 金额格式化 ¥，加仓绿色/减仓红色/持有灰色
- 顶部显示"当前生效总资金"，旁有「修改」按钮 → 弹出总资金输入框
- 底注"建议仅供参考，不构成投资建议"

### 块 B：总资金动态配置（Phase 1）

**新增 DB 配置项**（复用现有 config 表，若无则新建 `app_config` key-value）：
- key: `total_capital_rmb` / value: 金额字符串
- 默认：首次为空时，系统 fallback 用 `total_mv`（Σ当前市值）估算

**前端**：操作建议卡片顶部"总资金"输入框 → `PUT /api/config/total-capital` → 存配置
**后端分析时动态读**：`_build_portfolio_input` 改为：
1. 读 config `total_capital_rmb`
2. 有值 → 用它算仓位比例基准；无值 → 用 `total_mv`
3. `target_amount = total_capital × target_weight`（用总资金而不是 total_mv）
4. `action_amount = target_amount − current_mv`

**关键**：前端展示当前生效值，用户改一次 → 下一次分析自动用新值，无需重启/同步。

### 块 C：实际操作记录闭环（Phase 2, 你第6点核心）

**新增表 `trade_execution`**：
```
id, report_id, fund_code, fund_name,
suggested_action, suggested_amount, target_weight_pct,
actual_action(照做/未动/反向/加仓/减仓), actual_amount,
source(manual回填/diff自动比对), note, created_at
```

**记录方式**：
1. 前端卡片每行加「我已操作」下拉：照做/没做/反向/自填金额 → POST 记录
2. **自动比对**：后续 real 加仓/减仓(record_change) 时，反推 actual 并关联最近的建议

**校准**：`backtest_feedback` 增加"执行偏差"统计——"该加仓建议你上次未执行，少赚X%"→ 提示调整目标仓位。

### 块 D：自适应 NaN 修复（Phase 1 一并做，建议）

`adaptive_optimizer.py:216` 之前按最短净值对齐导致 NaN。修复：
- 各基金净值少于 `MIN_NAVS`(如 60) 时，**跳过**该基金参与该 risk_class 优化（不剔除用户，只剔除优化样本）
- 网格每段窗口 `rets` 长度 <3 时跳过该窗口（不 reduce）
- 产出 NaN 的条目丢弃并告警日志（不静默）
