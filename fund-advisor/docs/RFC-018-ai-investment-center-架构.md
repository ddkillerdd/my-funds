# RFC-018 · AI投顾"长期投资方案中心" — 架构设计

> 版本: v0.1 (2026-08-03) | 依赖: RFC-018-调研 | 前置: 现有系统零件齐全(RFC-010/012/014/017)
> 目标: 定义可扩展的六大模块架构, 串起"入场铺垫 → 长期跟踪锦上添花"闭环
> 命名: 本方案即用户口中的"入场辅助" —— 统一称"长期投资方案中心"(RFC-018)

### 数据流向 (一个方案的生命周期)
```
基金池(候选) → AI荐基(Top N + 理由) → 配比(干权重/份数) → 回测验证(历史战绩)
   → 资金簿+分批计划(100份/择时发车) → 用户确认 → 一键建仓写持仓
   → 该 Plan 进入每日顾问跟踪列表(长期锦上添花/补救) → 自适应WFA持续调优
```

## 2. 六大模块详述

### ① 基金池 FundPool (数据底座)
- **职责**: 提供全市场候选基金, 供 AI 主动荐基。
- **现状缺口**: 主库仅4只 → 需全市场池。
- **设计**:
  - 新表 `fund_candidate`: fund_code/name/type/style/scale/成立日/近1年收益/走势标签/是否开放申购。
  - 数据源: 天天基金全市场列表 API 温启动(拉列表 → 建池), 增量刷新 + 需求时临时拉净值(复用 sim_tmp_fund 思路)。
  - **关键**: 池子只存"候选元信息", 净值按需拉取缓存, 不无限占库。
- **扩展点**: 可加风格/行业/规模标签 → 支撑更细的 AI 筛选。

### ② AI荐基 Recommender (规则 + AI 双层)
- **职责**: 从基金池给出"**现在适合入场的 Top N 基金**" + 每个 AI 理由。
- **设计 (规则预筛 → AI研判)**:
  - **规则层 (确定性)**: 打分(动量/质量/回撤/分散/规模/估值) + 硬过滤(成立<2年剔除/净值异常/波动过高/**用户已持有基金——禁止重复**) → 收敛候选池到 ≤20 只。
  - **AI层 (灵活性)**: 把规则层的 Top 20 的量化特征喂给 LLM(NewAPI), 让 AI 结合"当前市场环境"研判"现阶段哪几只更适合入场 + 给理由 + 风险提示" → 输出 Top 5 左右。
  - 理由字段: 入场逻辑/当前适配/风险提示/一句话点评, 全部要求**人话**。
- **扩展点**: 可接更丰富的因子/AI多模型共识(与 RFC-001 思路一致)。
- **风控**: AI 结果必须**可被规则层核对**(不准推荐池子里没有/被硬过滤剔掉的基金)。

### ③ 智能配比 Allocator (拆份定权重)
- **职责**: 给选中的基金算**配比%(权重)**, 融入用户风险偏好。
- **设计**:
  - 基线: 复用现有 `suggested_ratio_pct`(打分分散微调)。
  - 叠加: 用户风险偏好(保守/稳健/激进) → 调整高风险基金权重。
  - 约束: 单只上限(如25%)/下限; **全部权重和=100%**。
- **扩展点**: 可接入均值方差/风险平价/目标波动率(引擎已在 fund-analyzer, 可逐步启用)。

### ④ 回测验证 Verifier (历史检验)
- **职责**: 用**这套配比**在历史上回测, 展示"过去赚多少/最大回撤/回撤修复时长/盈利概率"。
- **设计**:
  - 复用 simulator 引擎, 输入 = 配比折算的金额权重(预算×权重)。
  - 新增字段: `max_drawdown_recovery_days`(最大回撤修复时长), 借鉴雪球。
  - 展示: 一次性 vs 每月定投 两种路径对比(借鉴 Wallible)—— 契合分批计划。
  - **异步后台执行 + 轮询**(性能已验证), 不阻塞 UI。
- **扩展点**: 情景压力测试(回撤20%影响)。

### ⑤ 资金簿 + 分批计划 Planner (固定预算管理 & 且慢"100份")
- **职责**: 管好"固定预算", 生成**分批入场计划**, 不超支。
- **设计**:
  - 新表 `portfolio_plan`: total_budget/used/remaining/status/risk_profile/funds(配比)/批次计划。
  - **"100份"拆法**: total_budget ÷ 100 = 每份金额; 按择时信号(dca_planner 估值法)决定每批投几份。
  - 批次表 `plan_tranche`: 批次号/应投份数/择时信号/建议日期/状态(待执行/已执行)。
  - **每触发一次建仓, used+金额, remaining 扣减; 剩余为 0 / 全份投完 = 计划完成**。
- **扩展点**: 止盈目标(组合收益12%分批止盈, 借鉴富国"目标盈")。

### ⑥ 确认建仓 + 长期跟踪 (闭环出口)
- **职责**: 用户确认方案 → 一键把分批计划落地为真实持仓 → 该组合进入每日顾问跟踪。
- **设计**:
  - 确认: 前端展示完整方案 → 用户点"确认入场" → 调 simple_import 写 holdings(单只按份数×每份金额买入)。
  - 衔接每日顾问: 建仓后这些基金**自动进入 advisor 分析列表**(现有 create_holding 即入列表, 几乎零成本)。
  - 锦上添花: 每日顾问按建仓成本/浮盈给调仓建议; 自适应 WFA 持续优化参数。
- **扩展点**: 组合级每日看板(各基金收益贡献/再平衡提示)。

## 3. 数据模型 (核心新表)

```
fund_candidate (基金候选池)
  id, fund_code, fund_name, fund_type, style, scale, inception_date
  latest_nav, nav_change_pct, label(标签), open_apply(bool), status

portfolio_plan (投资计划 - 固定预算)
  id, name, total_budget, used_amount, remaining, risk_profile(conservative/balanced/aggressive)
  status(draft/active/completed), created_at, approved_at
  target_allocation(JSON: {fund_code: weight_pct})

plan_tranche (分批批次 - 100份)
  id, plan_id, tranche_no, units(应投份数), nav_signal(择时信号)
  plan_date, status(pending/executed), executed_at, amount

plan_holding (计划持仓明细 - 每个基金盈亏分开记录)
  id, plan_id, fund_code, fund_name
  total_cost(累计成本), total_units(份额), avg_cost(平均成本), last_nav, last_update
  → 方案: 计划内每只基金独立核算浮盈(不与全局 holdings 混合)
  → 建仓约束: 禁止重复 —— 候选/配比已剔除用户已持有基金(避免过度集中)

(复用) holdings / sim_tmp_fund / adaptive 等现有表
```

## 4. API 设计 (草稿)

| 方法 | 端点 | 职责 |
|------|------|------|
| POST | /api/plan/pool | 触发/刷新全市场基金池 |
| GET | /api/plan/pool | 候选池列表(可筛: 类型/风格/标签) |
| POST | /api/plan/recommend | AI荐基: 输入{budget, risk} → {funds: Top N + 理由} |
| POST | /api/plan/allocate | 配比: 输入{funds, risk} → {weights} |
| POST | /api/plan/backtest | 回测验证: 输入{weights, budget} → {历史战绩} (异步) |
| GET  | /api/plan/backtest/tasks/{id} | 轮询回测结果 |
| POST | /api/plan/{id}/tranches | 生成分批计划(100份) |
| POST | /api/plan/{id}/confirm | 确认入场 → 建仓 + 计划启用 |
| GET  | /api/plan | 我的计划列表 |
| GET  | /api/plan/{id} | 计划详情(预算/已用/批次/表现) |

## 5. 扩展性设计 (用户会不断加东西)

1. **模块解耦**: ①~⑥ 独立 service, 用 API 接口连接, 互不 import 对方内部 → 加新模块不动旧模块。
2. **AI 可插拔**: 规则层稳定 + AI层可换模型/多模型; AI 只做"研判/解释", 不做"凭空造基金"(受规则层约束)。
3. **数据即服务**: 基金池、配比、分批都做成可复用能力, 未来任何新功能(止盈/目标/复盘)都能调。
4. **分阶段落地**: 先打通主干(②④⑤⑥), 再补增强(①池温启动/⑦指标), 每期可验收。

## 6. 取舍与遵从前置约束
- **真实优先 / 不吹嘘**: 全市场池有幸存者偏差、AI荐基有幻觉风险 → 都做可控性设计(规则约束AI + 免责声明)。
- **预算不超支**: 资金簿是硬约束, 建仓必须扣余额。
- **复用不重造**: 回测/配比/建仓/每日顾问全用现成引擎, 只加编排层与产品层。
