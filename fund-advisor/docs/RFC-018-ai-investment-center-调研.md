# RFC-018 · AI投顾"长期投资方案中心" — 调研报告

> 版本: v0.1 (2026-08-03)
> 目标: 回答"借鉴了谁、我们有什么、缺口在哪", 为架构设计提供扎实依据
> 关联: RFC-010 (荐基引擎)、RFC-012 (回测自适应)、RFC-014 (仓位决策引擎)、RFC-017 (WFA自适应优化)

---

## 0. 产品定义 (一句话)

用户给一笔**固定的总预算**(如 100 元/10 万),系统用 **AI 荐基 + 智能配比 + 历史回测验证 + 长期分批计划** 生成一份**完善的入场与长期投资方案**;建仓后由每日 AI 顾问持续跟踪(锦上添花/补救)。

### 关键设计认知 (来自用户确认)
- **预算固定**: 所有建仓、分批、后续加仓都从这个池子出, 系统管好总额分配, 不超支。
- **入场 = 一次性铺垫决策**; **每日分析 = 建仓后的持续锦上添花/补救** —— 两者分开但衔接。
- **架构要可扩展**: 用户想法多, 会不断加东西; 模块解耦、接口隔离。

## 1. 借鉴了谁 (行业对标)

### 1.1 海外智能投顾 (Betterment / Wealthfront)
| 可借鉴点 | 描述 |
|---------|------|
| **KYC 风险问卷** | 先做风险测评 → 量身定制投资计划 → 实时监控 → 定期更新(始终落在容忍范围内) |
| **目标导向 (goal-based)** | 把"资产增值"这个大目标拆成多个小目标, 每个目标独立配组合+存入计划 |
| **自动再平衡** | 季度/年度自动把配置拉回目标比例 |
| **成本/税收优化** | 优先低费率 ETF、tax-loss harvesting(对我们A股基金参考意义小, 但"费率意识"可借鉴) |
| **费率透明** | 平台费 0.25% 上下, 公开定价 |

> 启发: 我们的"入场方案"应包含 **风险偏好输入 + 目标配比 + 自动再平衡逻辑**, 并贯穿"固定预算"的资金管理。

### 1.2 国内·盈米"且慢"
| 可借鉴点 | 描述 |
|---------|------|
| **"100份"分批建仓策略** | 把总预算拆成 100 份, 按估值/择时信号分批投入 → **完美契合用户"固定预算100元分批入场"** |
| 长盈指数投资计划 | 以指数/ETF 为主, 分批投入/定投, 控制成本, 拉长周期 |
| 择品+择时策略注入AI | 华安投顾把"选什么(择品)""什么时候买(择时)"批量注入 AI 智能体 |

> 启发: 用户的"100元"可以类比且慢"100份"——**固定预算拆份 + 分批 + 择时发车** 是成熟且被验证的模式, 我们直接可用。

### 1.3 工具类 (Portfolio Visualizer / 元大 / Wallible / 雪球)
详见上一轮调研(2026-08-03-入场调研.md), 核心可借鉴:
- **多组合并排对比** (PV)
- **回测支持"一次性 vs 每月定投"** (Wallible) → 契合"分批计划验证"
- **组合命名保存 + 长期跟踪** (元大)
- **最大回撤修复时长** 指标 (雪球, 且被指"缺再平衡"是硬伤 → 我们已有波动率调仓, 比它强)

### 1.4 券商 AI 投顾 (中信建投/广发/富国 等)
| 可借鉴点 | 描述 |
|---------|------|
| **全链路决策辅助** | 持仓诊断→策略生成→动态调仓→风险预警→调仓提醒 = "从人找服务到服务找人" |
| **AI拟人陪伴** | 富国"社群+发车+实盘": 按风险分级建群, 实盘跟投/纪律定投/目标盈, 情绪陪伴 |
| **AI智能体 + 专业工具注入** | 广发把资产配置框架/账户收益/基金信息接入 Agent 平台; 盈米用 MCP Server 标准化封装基金数据+投顾算法 |
| **知识体系数字化** | 华安把投顾沉淀的策略/择品/择时注入 AI 可学的"知识库" |

> 启发: 我们的"AI荐基"应是 **规则因子打分(已有/确定性) + AI 大模型研判/解释(新增/灵活性)** 的双层结构, 而非纯规则或纯 LLM。

### 1.5 AI 组合管理策略师 (Jenova AI 型工具)
| 可借鉴点 | 描述 |
|---------|------|
| **漂移与再平衡** | 当前权重 vs 目标权重对比, 超阈值触发再平衡建议, 以金额/份数量化 |
| **情景建模/压力测试** | 股市回撤20%等冲击对组合的影响 |
| **业绩归因** | 回报分解为配置/选券/择时效应 |

> 启发: "长期指导"部分应含 **再平衡明细(改多少份/金额) + 情景压力测试(最坏亏多少)**, 这些比"泛泛建议"更有实战价值。

## 2. 我们有什么 (现有系统能力盘点)

| 模块 | 现状 | 文件 |
|------|------|------|
| **荐基打分+配比** | ✅ 6因子(total_score)+ suggested_ratio_pct | `engine/screener.py::screen_funds` |
| **AI荐基解释** | ✅ 可选 LLM 解释 | recommend_service |
| **择时** | ✅ action_label + risk_gate + dca_planner(分批金额%) | `engine/timing.py` |
| **回测** | ✅ 多窗口/每日盈亏/净值走势/回撤; 支持 target_vol/friction | `engine/simulator.py` + SimulatorView |
| **自适应寻优(WFA)** | ✅ 参数寻优+采纳机制 | RFC-017 |
| **仓位决策引擎** | ✅ build_position_action (每日顾问用) | RFC-014 |
| **建仓/持仓** | ✅ create_holding + simple_import | holding_service |
| **每日AI顾问** | ✅ 每天分析+建议 | advisor_service |
| **基金数据** | ⚠️ 可拉任意基金历史(临时表); 主库仅4只 | sim_tmp_fund / nav_service |
| **AI模型** | ✅ NewAPI (minimax-m3/step-3.7/deepseek) | NewAPI|

**核心结论: 90% 的"零件"已存在且经生产验证** —— 缺的不是零件, 而是:
1. 把这些零件**串成一个"从入场到长期跟踪"的闭环**的编排层
2. 面向"固定预算 + 主动荐基 + 完整长期方案"的**产品形态(UI/API)**
3. **全市场候选池**作为 AI 主动荐基的数据来源(主库只有4只)

## 3. 缺口分析 (每缺口的严重度/方案方向)

| # | 缺口 | 严重度 | 方案方向 |
|---|------|:---:|---------|
| 1 | **全市场候选池**(AI主动荐基数据源) | 🔴高 | 建 `fund_candidate` 池表(代码/名称/类型/风格/规模/近况), 用天天基金全市场列表温启动 + 增量 |
| 2 | **"固定预算"资金簿管理** | 🔴高 | 新 `portfolio_plan` 表: 总额/已用/剩余/分批计划; 所有建仓记录归属该计划 |
| 3 | **AI从候选池主动筛"适合入场"** | 🔴高 | 规则预筛(打分/流动性/成立年限)→ AI研判(当前市场适配)→ 输出 Top N |
| 4 | **配比%→具体金额/份数 + 分批计划** | 🟠中 | 复用 dca_planner + 且慢"100份"思路, 预算拆份+择时发车 |
| 5 | **入场→回测一键验证(打通)** | 🟠中 | 荐基配比自动喂 simulator(本次用户核心诉求) |
| 6 | **"保存为组合"+长期跟踪** | 🟡低 | 入场确认后存 `portfolio_plan` → 进每日顾问跟踪列表 |
| 7 | **回撤修复时长 / 压力测试指标** | 🟡低 | 回测输出加指标(借鉴雪球/Jenova) |

## 4. 风险与边界 (必须诚实声明)

### 4.1 数据风险
- **幸存者偏差**: 全市场候选池若只含现存基金, 历史回测偏高 → 需标注"清盘基金不含"。
- **历史≠未来**: 所有工具最后免责声明都这句; 回测是后视镜。

### 4.2 模型风险
- AI 荐基若用 LLM 主动筛全市场: 慢、贵、可能幻觉、不稳定 → **先规则预筛收敛池子, AI 只在候选子集上研判/解释**, 兼顾速度与质量。
- 冷启动: 新基金历史短, 回测/自适应会出现"数据不足"→ 已有处理(返回保守默认)。

### 4.3 合规声明
- 系统所有输出定位"辅助参考/信息", 不构成投资建议; 最终决策与盈亏由用户自负。
- 页面须带免责声明, 尤其"AI荐基"与"长期方案"。

### 4.4 技术风险
- 主库仅4只基金, 全市场池需温启动(拉列表+逐个拉净值, 量较大) → 分批缓存。
- 回测性能: 已改异步后台任务; 组合回测建议后台执行+轮询。

---

## 5. 结论: 为什么"先写文档、不急着写代码"是对的
- 现有零件齐全, 但**缺编排层 + 产品形态 + 数据池(全市场候选)** 三件大事。
- 三件事相互依赖(配比要资金簿、荐基要候选池、验证要配比), 必须先定架构再动手, 否则会返工。
- 行业已验证的"固定预算拆份+分批+择时"((且慢100份)、"KYC+目标导向"(Betterment)、"规则+AI双层选基"(券商)) 给了清晰可落地的范式。
