# RFC-018 · AI投顾"长期投资方案中心" — 开发计划

> 版本: v0.1 (2026-08-03) | 依赖: 调研 + 架构 + 详细设计
> 原则: 分期落地、每期可验收、复用现成零件、先行渐增

---

## 总体: 4 期 (Phase 0-3), 每期完成即有可用产物

```
Phase 0  打底: 数据库 + 基金池
Phase 1  主干: AI荐基 + 配比 + 回测验证 (用户最关注的"荐基⇄回测")
Phase 2  闭环: 分批资金簿 + 确认建仓 + 每日顾问接入
Phase 3  增强: 指标完善 + 组合看板 + 可选扩展
```

---

## Phase 0 — 打底 (数据底座)

### 目标
可用的全市场候选基金池 + 新增表。

### 交付
- [ ] 4 张新表: `fund_candidate` / `portfolio_plan` / `plan_tranche` / `plan_holding` (models + migration)
- [ ] `FundPoolService`:
  - 温启动: 拉天天基金全市场列表 → 建候选池(分批, 避免超时)
  - 增量刷净值(nav_service 复用)
  - API: POST /api/plan/pool (触发刷新), GET /api/plan/pool (查询/筛选)

### 验收标准
- 池里有 ≥100 只基金候选元信息(含类型/风格/规模/成立日)
- GET 池接口可按类型/风格筛选
- 新增表可正常 CRUD

---

## Phase 1 — 主干: AI荐基 + 配比 + 回测 (核心价值)

### 目标
把"荐基 ⇄ 回测"打通, 形成"AI挑基金 → 配比 → 历史验证"主干。**这是用户原始诉求。**

### 交付
- [ ] `PlanRecommenderService`: 规则预筛(Top20) → AI研判(Top5 + 理由)
- [ ] `PlanAllocatorService`: 配比权重 + 风控约束(上限25%/下限5%/归一化 + **禁止重复: 剔除已持仓基金**)
- [ ] `PlanBacktestService`: 桥接 simulator + 异步任务 + 回撤修复时长
- [ ] 后端 10 个 plan API(见详细设计 §6; 池×2+荐基+配比+回测+任务轮询+分批+确认+列表+详情)
- [ ] 前端 `PlanWizard` 前 4 步(预算偏好 → AI荐基 → 配比 → 回测验证)

### 验收标准
- 给 {budget=100, risk=balanced} → 返回 Top5 基金 + 理由 JSON
- 配比求和=100%, 单只不超25%
- 点"回测验证" → 异步出该组合的收益/回撤/修复时长
- 前端能完整走完 4 步看到结果

---

## Phase 2 — 闭环: 分批 + 建仓 + 长期跟踪

### 目标
方案从"看"变"可执行", 并进入每日顾问长期跟踪(锦上添花)。

### 交付
- [ ] `PlanService` 编排(create/confirm/tranche): 100份拆法 + 择时信号分批
- [ ] 分批计划展示(Step 5)
- [ ] 确认入场: 逐批调用 `simple_import` 建仓, 同时每只基金写 `plan_holding`(累计成本/份额/平均成本独立核算盈亏), **扣余额不超支**, 计划状态机 draft→active→completed
- [ ] 建仓后基金自动进每日顾问跟踪列表(顾问按 plan_holding 报该计划浮盈)
- [ ] 前端 Step 6 确认 + 我的计划管理

### 验收标准
- 100 元预算, 分批执行时 used+金额、remaining 正确扣减, 永不超支
- 确认建仓后 holdings 有记录, 每日顾问报告包含这些基金
- 计划完成(剩余=0或全份投完)状态正确

---

## Phase 3 — 增强 (可选, 按需)

### 目标
锦上添花的打磨 + 用户新想法入口。

### 候选增强(按优先级)
- [ ] **每日顾问接入 plan**(组合级每日看板: 各基金收益贡献/再平衡提示)
- [ ] 一次性 vs 每月定投 双路径回测对比图(Wallible 借鉴)
- [ ] 拆份时加入自适应(WFA)优选参数
- [ ] 止盈目标提醒(组合收益达 X 分批止盈, 富国"目标盈")
- [ ] 情景压力测试(回撤20%对组合影响)
- [ ] 交叉/相关性分析(避免同因子基金扎堆, AI组合管理师借鉴)
- [ ] 风险测评问卷(KYC)简化版(保守/稳健/激进 单选已够起步)

## 资源/风险
- **后端重启**: sudo systemctl restart fund-advisor-backend
- **前端**: fund-advisor-frontend.service(vite HMR 自动加载)
- **性能**: 回测异步后台 + 轮询(已验证)
- **数据量**: 温启动全市场池耗时较长, 分批跑 + 进度提示; 冷启动阶段 AI 荐基可先基于"用户输入的候选 + 现有持仓基金"兜底
- **合规**: 所有产出入免责声明(已纳入提示词/页面)

## 里程碑回顾 & 验收节奏建议
| 里程碑 | 内容 | 建议验收 |
|--------|------|---------|
| M0 (Phase0) | 基金池可用 | 你: 能不能筛到候选基金 |
| M1 (Phase1) | AI荐基→配比→回测打通 | 你: 100元方案能不能看到"该买哪些+历史战绩" |
| M2 (Phase2) | 分批+一键建仓+长期跟踪 | 你: 能不能真建仓并每天跟踪 |
| M3 (Phase3) | 增强打磨 | 按你新需求追加 |

> **建议**: 先做 Phase1 的 M1 (AI荐基→配比→回测), 这是你核心诉求且能最快看到"闭环"形态; M0 的池可先用"小候选集"过渡, 不必等全市场温启动。
