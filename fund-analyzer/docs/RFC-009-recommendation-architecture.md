# RFC-009: 荐基引擎 + 入场时机 — 基金分析能力重构总纲

> **状态**: ✅ 已落地 — Market Data Layer (`engine/market_data.py` + `engine/screen_runner.py`)
> **日期**: 2026-07-31
> **作者**: AAA
> **前置**: RFC-005（多模型辩论）、RFC-006（分析质量强化）
> **关联**: RFC-007（入场时机，将在本总纲下拆分落地）
> **目标**: 把 FundAnalyzer 从「持仓分析器」升级为「持仓分析 + 荐基 + 择时」三位一体的投顾内核，同时针对服务器资源（3.6GB RAM / 0 swap / East Money 单一数据源 / NewAPI 多模型）做可行性约束。

## 一、现状盘点（读完整个项目后的判断）

### 1.1 已有能力（优质，值得保留）

| 模块 | 优点 | 缺点 |
|------|------|------|
| **量化层** `quant.py` | 32 项指标全部 Python，零 LLM，NAV-only 计算，抗幻觉 | 无基准参数（`compute_all` 没传 `market_navs`）；无同类对比 |
| **组合量化** `portfolio_quant.py` | 相关矩阵/HHI/有效前沿/风险平价 | 有效前沿用蒙特卡洛，.3G 内存下模拟次数受限 |
| **多模型辩论** RFC-005 | 认知多样性 + 两层裁决，方法先进 | **ds-flash 是价值/debate 主力但 33% overload** → 实际大量降级 |
| **分析质量** RFC-006 | 决策矩阵/fallback 区分/交叉验证回写，设计完备 | **代码未实现**（`fallback_debate` 仍全 hold；`action` 无 `change_pct`） |

### 1.2 关键缺口（本次要补的）

1. **荐基能力为零**：只能分析「已持有的基金」，无法回答「该买什么」。
2. **择时/入场时机为零**：用户痛点「不知道何时入场」无解。
3. **无外部市场/基本面数据**：只吃 NAV，连沪深300 基准都没注入。
4. **RFC-006 停在纸面**：决策矩阵、fallback 强化、交叉验证回写都未落码。
5. **RFC-007 从未落盘**：设计在脑子里，文件不存在。

### 1.3 服务器硬约束（决定方案可行性）

| 资源 | 值 | 约束 |
|------|-----|------|
| 内存 | 3.6GB（可用 ~1.4GB） | 蒙特卡洛模拟、大型 DataFrame 需控制 |
| Swap | **0** | 峰值 >3.6G 会 OOM 卡死 |
| 磁盘 | 24GB 可用 | 本地缓存可，勿存海量数据 |
| 数据源 | **仅 East Money API**（`nav_fetcher.py`）| akshare 未装，评估是否值得引入 |
| LLM | NewAPI 多模型，rate-limited | ds-flash 不稳定，需重 fallback |
| 网络 | 有公网,可访问东财 | 可抓净值/估值/持仓 |

## 三、分层设计

### 3.1 Market Data Layer（新，复用东财 API）

不引入 akshare（省 300MB+ 依赖，规避东财反爬差异），直接在 `nav_fetcher.py` 上扩展。新增抓取：

| 数据 | 东财接口 | 用途 |
|------|---------|------|
| 沪深300/创业板/中证500 指数净值 | `index` 净值接口 | 大盘基准、β/α |
| 同类基金均值 | `fundRanking` 排名接口 | PeerBenchmark 分位 |
| 基金规模/成立日期/基金经理 | `fundDetail` | 规模稳定性、经理任期 |
| 重仓股/行业配置 | `fundPosition` 持仓接口 | 风格暴露、相关性解释 |
| 估值百分位（可选） | `fundNavGrow` 或历史 PE | 择时估值模块 |

> **落地约束**：这些接口按需抓取（仅分析/荐基时），不常驻轮询；结果缓存到磁盘 `data_cache/`（24GB 够用），避免重复打东财被封。

### 3.2 Entry Timing（RFC-007 落地）

六流派整合的择时评分（详见 RFC-007 文件）：
- **估值**：历史分位（PE/PB percentile）
- **技术**：MA/RSI/MACD 六因子打分（P0，纯 NAV 即可算）
- **趋势**：均线多头/空头排列
- **情绪**：成交额/新发基金（东财可得则用）
- **定投**：均线成本法 + 估值法双模式
- **风控**：回撤、波动率状态

输出：`EntryRecommendation`（时机评分 0-100 / 建议：now_entry / staged / wait / avoid / 定投触发）。

### 3.3 Fund Screener（RFC-008 荐基 — 本次核心新增）

**多因子打分 + 风格分类 + AI 解读**，从候选池（东财热门/同类基金列表）筛出适合当前组合的基金。

**打分因子**（全部量化可算）：
| 因子 | 权重 | 计算 |
|------|------|------|
| 动量 | 20% | 3m/6m/1y 收益，风险调整 |
| 质量 | 20% | Sharpe/Sortino/Calmar 综合 |
| 回撤控制 | 15% | 最大回撤、当前回撤、恢复天数 |
| 相关性互补 | 20% | 与现有组合平均相关（越低越好） |
| 规模/流动性 | 10% | 规模 >2亿，非迷你基金 |
| 估值安全 | 15% | 估值分位（若可抓） |

**输出**：候选基金排序 + 每只的「风格标签」+「为什么适合你」（AI 简短解读）+「建议仓位」。

### 3.4 Portfolio Optim（增强）

现有有效前沿升级：用 `scipy` 或轻量 Markowitz（限制模拟次数控制内存），输出到「荐基」的目标权重，而不是只给持仓诊断。

## 五、实施顺序（分阶段，每阶段可独立交付）

### Phase A（P0，最先）— RFC-006 代码落地
让现有「持仓分析」先达标：决策矩阵、fallback 差异化、交叉验证回写。**无新数据源依赖。**

### Phase B（P0）— RFC-007 择时 v1（纯 NAV 技术面择时）
不依赖外部数据，先上技术因子（MA/RSI/MACD/回撤）。立即可用。

### Phase C（P1）— Market Data Layer + PeerBenchmark
抓沪深300基准 + 同类均值，注入 RFC-006 方案 D。补折当前「无参照系」的短板。

### Phase D（P1）— RFC-008 荐基 v1
在 C 的同类数据上做 Screener：同类打分 + 相关性互补 + 规模过滤 + AI 解读。

### Phase E（P2）— Portfolio Optim 升级 + 完整闭环
荐基输出「目标权重」→ 组合再平衡建议量化。

## 七、风险与约束

| 风险 | 缓解 |
|------|------|
| 东财接口反爬/字段变动 | 抓取失败静默降级（无基准数据则提示「数据不足」），不阻塞分析 |
| 内存不足（3.6G） | 蒙特卡洛降为定向模拟；数据按需加载；加 swap（建议 2G，治本）|
| ds-flash 不稳定 | 所有 LLM 步骤保留 omni/nano 降级链 |
| 荐基责任风险（不是投顾） | 所有输出带「非投资建议」免责 + 置信度 + 使用量化硬数据 |
| 相关性与择时对历史依赖 | 冷启动数据不足时明确标注 data_quality |
