## 🚀 高优先级（用户可直接感知）

### 1. 并行化 LLM 调用 — 耗时 14min → 5min
**问题**: 4 基金 × 4 视角 = 16 次 view 调用全部串行，每次等 omni-30b 30s
**方案**: 同一只基金的 4 个视角并行调用（4 个不同模型同时发请求），等最慢的返回后拼 debate
**收益**: 16 次串行 → 4 轮并行（每轮 ~40s），view 阶段从 ~500s → ~160s
**风险**: NIM 40 calls/min 限制，4 并发不会触顶
**注意**: debate 必须等 4 个 view 全部完成，不能跨基金并行（NIM 限流）

### 2. 前端加载分析结果不需要等分析完成
**问题**: 点击"开始分析"后页面卡 14 分钟无反馈
**方案**: 
- 后端 POST /analyze 立即返回 `job_id`，分析在后台跑
- 前端轮询 `GET /analyze/status/{job_id}` 显示进度（"正在分析第 2/4 只基金..."）
- 完成后自动加载结果
**收益**: 用户不用盯着空白页面等

### 3. 前端"分析中"进度条
**问题**: 当前无进度提示
**方案**: 后端 SSE（Server-Sent Events）或简单分步返回 — 每完成一个步骤推一条消息
- `step: "analyzing fund 1/4: 景顺沪深300"` 
- `step: "trend view done (omni-30b, 30s)"`
- `step: "debate done (ds-flash, 25s)"`
- `step: "complete"`
**收益**: 14 分钟的等待不再黑盒

## 🟡 中优先级（体验优化）

### 4. 自动定时分析 — cron 自动跑
**问题**: 目前只有手动触发
**方案**: cron 工作日 09:00 自动执行分析（利用已有的 cron 机制）
**注意**: 需要把现在的 cron job `FundAdvisor daily analysis push` 切到 v3 engine

### 5. 报告对比功能
**问题**: 18 篇报告之间无关联，无法看变化趋势
**方案**: 前端加一个"对比"按钮，选 2 篇报告并排显示 health_score 变化
**收益**: 看到"161725 白酒上次 health=60 这次降到 45"这样的趋势

### 6. max_tokens 精简
**问题**: 所有调用 max_tokens=4096，但很多视角输出 500-800 token 就够
**方案**: 
- view 分析: 2048（够 3-5 条诊断+总结）
- debate: 4096（需要完整矛盾+共识分析）
- cross_val: 1024（checklist 核对，短输出）
- portfolio: 4096（全局分析）
**收益**: 每次调用减少 50% max_tokens → NIM 响应更快（生成 token 少=等的时间短）
