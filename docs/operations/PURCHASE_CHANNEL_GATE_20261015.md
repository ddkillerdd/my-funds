# MF-PURCHASE-GATE1-20261015-01：渠道与含费付款门禁

## 状态与边界

本轮是本地实现和离线验收，不是生产发布。没有 SSH、Git 写入、部署、数据库连接或写入、外部模型、报告生成、邮件、自动交易或真实持仓操作。

实现新增的申购门禁及页面显示，不宣称提高预测准确率或已证明策略可以盈利。后续真实净收益归因、样本外回测、赎回费用分笔核算不在本轮完成范围。用户表示可承受从1000元跌到800元，记录为约20%的组合回撤偏好，不直接变更既有单基金止损参数，也不保证把实际亏损限制在20%。

## 数据流

`AdvisorService -> apply_execution_policy_from_db -> 只读 app_config 与 trade_execution -> apply_execution_policy -> plan_purchase -> 报告JSON -> 顾问页面`

- 新读取已有配置表的键 `purchase_channel_quotes_v1`，值为 JSON 对象列表。**本轮不创建该键、不写任何配置值、不新增写接口。**
- 运行时未实现支付宝/天天基金账户登录、账户额度抓取或自动跨平台询价。运营端经具体授权取得账户级证据后，才能向服务器已有配置表提供核验快照；公共网页只能作为候选信息，不能把 `public_only` 自动升级为 `account_confirmed`。
- 不把聊天里的截图费率、现有持仓、银行卡或账户标识硬编码进程序。新测试全部使用虚构基金和平台；原有四基金行情映射测试继续保留。
- 缺键、空快照、暂停、未知费率或额度、过去日期、未来时间、无时区、超过30分钟、同渠道重复证据，均不形成正向付款。
- **直接部署但没有可信快照供给，会使所有买入候选归零。故本版尚不能作为“全自动渠道核验已完成”上线。**

## 快照合同（仅合成示例）

```json
[
  {
    "fund_code": "000001",
    "platform": "合成平台甲",
    "payment_method": "合成支付",
    "purchase_status": "open",
    "account_eligible": true,
    "evidence_scope": "account_confirmed",
    "subscription_fee_rate_pct": "0.15",
    "fee_mode": "proportional",
    "min_purchase_rmb": "1.00",
    "daily_remaining_rmb": "100.00",
    "observed_at": "2026-10-15T13:55:00+08:00",
    "source": "合成核验来源"
  }
]
```

日期仅供测试，不能刷新时间戳冒充重新核验。`0.15` 表示0.15%，不是15%。`daily_remaining_rmb` 是账户在该渠道当前剩余额度，不是公告总上限；`account_eligible` 必须来自账户级证据。没有官方确认的无限额不能伪造一个大数字代替未知。

同一 `fund_code + platform + payment_method` 只能有一份有效证据。只比较同代码的已核验渠道申购费率，费率相同优先能容纳较多候选付款者，仍不比较不同基金、不同份额类别和持有期总成本。

## 金额怎么算对

1. 仍由原量化规则产生候选方向与金额，原分析质量、日20元/月200元、单日一只、冷却门禁先执行，不放宽阈值。
2. 付款上限为候选金额、跨平台日预算余额、跨平台月预算余额的最小值，再受已核验渠道剩余额度限制。向下取整到分，不能为了达到起购额突破上限。
3. 总付款包含申购费：`净申购金额 = 总付款 / (1 + 申购费率百分数 / 100)`；净金额按分四舍五入，申购费等于总付款减净金额。只支持比例外扣估算，固定费率或特殊收费方式拦截。
4. 合成断言：20元、0.15%费率 -> 净投入19.97元、手续费0.03元，总和20元；0.06% -> 约0.01元；0.12% -> 约0.02元。以平台最终确认金额、净值和份额为结算依据，不按估计净值编造真实份额。
5. 合成断言：平台甲已付款5元、乙7元、本月其他185元 -> 本月剩余3元；负向卖出80元不补回买入预算。
6. 合成断言：渠道剩余8元、起购10元 -> 最终0元；若起购1元 -> 最多8元。首选基金暂停时保留现金，不自动挪给第二只或生成预约。

管理费、托管费、销售服务费若已计入基金净值，不能再从该净值收益重复扣除。当前只估算申购费，不计算卖出分批持有期限与赎回费，报告明确 `redemption_fee_checked=false`。历史 `trade_execution.actual_amount` 仅复用已有记录，未对账的旧金额不能被追溯宣称为含费实际成交；当前反馈仍不自动改持仓或现金、不能消歧多平台真实成交。

## 接口与页面影响

- 不变更数据库schema、迁移、依赖、环境变量或现有HTTP路由。
- 报告JSON新增 `actions[].purchase_check`，包含渠道、支付方式、证据时间、总付款、预计手续费和净投入、阻止原因、人工交易边界；`execution_policy` 增加含费预算口径与时效说明。
- 旧报告缺少渠道字段时不展示为当前可执行正向付款；页面每15秒本地更新时间，超过30分钟或跨上海日期后隐藏付款预览。该本地计时器不产生API请求或后台任务。
- 页面所有金额保留两位小数。健康分析和资金分配显式标为量化候选，命中率改为历史方向核验，并声明不是赚钱概率或实盘收益。
- 已保存报告的 `purchase_check` 只代表报告计算时的快照，不是持续交易许可。邮件渲染器及 OpenClaw 本轮未改，尚未验收新字段与邮件发送前的快照时效，不能声称邮件已具备本轮能力。

## 发布前的固定剩余项

1. 在另行授权的生产只读阶段核对当前运行代码与本地基线差异；本地 HEAD 不能推断生产代码完全相同。
2. 确定可信账户快照的供给方式；默认不登录投资账户，不自动交易，不凭公共费率页面伪造账户资格和剩余额度。
3. 对新字段、旧报告、未供快照和报价过期分别完成生产邮件呈现验收；保留既有每日一次邮件幂等规则。
4. 获得明确的Git/部署/必要配置写入授权后，固定提交发布并验证；本轮未进行这些动作。

## 用户当前操作

现有持仓不因暂停申购而自动卖出。不要把预约当提醒，不为买不到纳指就自动加到恒生科技或A500。本轮不产生新的立即买入指令，不消耗预算。发生真实交易后，保留基金代码、平台、总付款、实际手续费、确认份额、确认净值及确认日期，再按真实记录更新；不要仅凭截图市值涨跌修改份额。
