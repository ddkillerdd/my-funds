# Sol、Luna 与 OpenClaw 长期协作规范

> 生效日期：2026-09-03
> 适用范围：`E:\myfund11111` 的长期规划、开发、测试、Git 固化、staging、生产维护与故障处理
> 默认方式：用户停留在 Sol 指挥任务；Sol 后台调度同一 Luna 执行任务；OpenClaw 只承担已登记的生产职责

## 1. 目标

本规范解决以下长期问题：

- 用户不再在 Sol 与 Luna 之间手工复制长篇结果和指令。
- Sol 与 Luna 的模型上下文彼此隔离，不把一个任务的完整历史灌入另一个任务。
- 两个任务虽然共享同一个项目目录，但同一时刻只有一个写入者。
- 用户只在 Sol 指挥任务进行授权、变更范围和最终决策。
- Git 推送、服务器写入、服务控制、数据库操作和生产切换分别设置确认门。
- Codex 重启、任务压缩、模型切换或执行任务更换后，仍可从仓库文档恢复准确状态。

本规范不降低 `AGENTS.md`、阶段执行令、生产安全规则或用户最新指令的优先级。

## 2. 固定角色

### 2.1 用户

- 只需在 Sol 指挥任务中说明目标、确认或拒绝下一阶段。
- 对服务器写入、服务停止/启动/重启、数据库操作、Git 推送、staging 部署和生产切换分别授权。
- 不在 Luna 执行中途同时发送另一套范围不同的指令；如需改变任务，先在 Sol 要求中止或调整。

### 2.2 Sol 指挥任务

- 负责理解目标、审查 Luna 结果、划分阶段、确定风险、验收标准、停止条件和回滚。
- 直接读取 Luna 任务状态与最终结果，不要求用户复制转发。
- 只把当前阶段所需的增量指令发送给 Luna，不发送 Sol 的完整聊天历史。
- Luna 运行期间保持只读，不修改共享工作区、不操作服务器、不改变 Git 状态。
- 任何需用户确认的动作先在 Sol 汇报；只有用户在 Sol 明确授权后，才把授权范围转交 Luna。
- 默认不切换用户当前窗口；只有用户明确要求观察 Luna 时才导航到 Luna 任务。

### 2.3 Luna 执行任务

- 是本项目默认唯一执行端，负责经授权的文件修改、测试、构建、Git 操作和服务器操作。
- 每次只执行 Sol 发送的一项阶段任务，不自行扩展到下一阶段。
- 开始前读取 `00_LUNA_START_HERE.md`、`LUNA_HANDOFF.md`、当前阶段执行令和相关运维文档。
- 写操作前重新核对时效性状态，不把聊天或旧文档中的 PID、SHA、端口和服务状态视为永久事实。
- 阶段结束时按本规范的结果格式汇报，并在授权范围内同步交接文档。
- 不直接要求用户去 Sol 复制信息；只需在自身任务中完整结束当前阶段。

### 2.4 OpenClaw

- 继续承担已明确登记的生产观察、自动任务或经用户确认的紧急操作。
- 不与 Luna 同时修改相同文件、Git 工作区、服务或数据库对象。
- 生产控制范围不清楚时，Luna 和 Sol 都停止写操作，先只读确认。

## 3. 上下文、缓存和共享状态边界

### 3.1 对话上下文

- Sol 与 Luna 是两个独立任务，各自保留自己的消息历史和模型上下文。
- Sol 读取 Luna 结果不会把 Sol 的历史写入 Luna。
- Sol 向 Luna 发送消息时，只有实际发送的消息进入 Luna 上下文。
- 窗口是否显示 Luna 不影响 Luna 的任务上下文；界面导航只改变用户看到的任务。

### 3.2 缓存原则

- 缓存只用于性能优化，不能作为正确性、状态持久化或交接依据。
- 长期复用同一个 Luna 执行任务，并保持稳定、简洁的指令前缀，有利于上下文复用。
- 动态状态放在提示词末尾或交接文档中；不要每次重复粘贴全部历史报告。
- 不能假设某次一定命中缓存，也不能因担心缓存而省略安全边界或实时复核。

### 3.3 额度原则

- 安全规则只在 `AGENTS.md` 和本文件定义一次；阶段提示引用文件与章节，不重复粘贴全文。
- 固定规则放在执行包前部，阶段名称、SHA、文件清单和实时状态等动态内容放在末尾，保持稳定前缀。
- 新任务或恢复不确定时完整读取核心文档；同一 Luna 任务连续执行时，只读取发生变化的入口、交接、阶段章节和 Git 差异。
- 历史阶段文档默认不重读；只有当前交接引用其证据、出现漂移或需要审计时才读取对应章节。
- 成功路径只返回结论和验收摘要；失败时才追加最小错误片段，不返回完整日志或重复命令输出。
- 不以减少额度为理由跳过保护文件哈希、敏感信息检查、外部写操作确认或状态切换前的实时复核。

### 3.4 共享状态

以下对象在两个任务之间真实共享，必须按单写入者规则管理：

- `E:\myfund11111` 文件和 Git 工作区。
- 本地依赖目录、Docker 资源和临时 worktree。
- GitHub 分支和提交。
- 生产服务器、OpenClaw、systemd、cron、进程、端口和数据库。

上下文不会自动串线，但共享对象会被另一任务立即看到。因此，防污染的关键是单写入者和阶段锁，而不是切换窗口。

## 4. 固定任务识别

- 默认指挥任务：项目路径为 `E:\myfund11111`、标题为 `sol` 的现有任务。
- 默认执行任务：项目路径为 `E:\myfund11111`、标题为 `luna` 的现有任务。
- Sol 每次调度前通过任务列表同时核对标题、项目和工作目录，不只依赖标题。
- 内部任务 ID 不写入仓库文档；它属于应用状态，可能在重新创建任务后变化。
- 未经用户明确要求，不自动创建新的执行任务；优先继续现有 Luna 任务。
- 出现多个同名 Luna 任务、目标任务正在运行或任务来源不清时，不发送指令，先向用户汇报。

## 5. 单写入者与阶段锁

任一时刻，本项目只能处于以下一种状态：

1. `SOL_PLANNING`：Sol 只读规划，Luna 空闲，不允许项目写入。
2. `AWAITING_USER_APPROVAL`：等待用户在 Sol 授权，不允许任何写入。
3. `LUNA_DISPATCHED`：指令已发送，等待 Luna 开始；Sol 不写入。
4. `LUNA_RUNNING`：Luna 是唯一写入者；Sol 只等待或读取状态。
5. `LUNA_NEEDS_ATTENTION`：Luna 遇到停止条件；保持现状，等待用户决策。
6. `LUNA_COMPLETED`：Luna 已完成；Sol 读取结果并做只读验收。
7. `SOL_REVIEW`：Sol 形成结论和下一授权门；不得擅自开始下一阶段。

禁止 Sol 与 Luna 同时编辑本地文件、运行会写缓存的测试、操作 Git、创建容器或操作服务器。

如果用户直接在 Luna 中发送了新消息，Sol 将其视为可能改变执行范围；在读取并确认前不再向 Luna发送另一条指令。

## 6. 标准调度流程

### 6.1 用户提出目标

用户在 Sol 中提出目标或确认下一阶段。Sol 先判断属于：

- 只读调查或审查。
- 本地文件修改、测试或构建。
- Git 暂存、提交或推送。
- staging 写入或部署。
- 生产服务、配置或进程操作。
- 数据库操作。
- 生产切换或回滚。

不同类别不能用一次模糊的“继续”自动合并授权。

### 6.2 Sol 形成执行包

日常执行包默认只包含 7 个字段：

```text
阶段与目标：
依据：核心文档、当前执行令与必要章节
已授权：本阶段允许的写操作
禁止：外部动作、保护对象和范围边界
验收：必须通过的检查
停止与回滚：触发条件和已授权回滚
基线增量：分支、SHA、差异和时效性快照
```

提示词引用仓库内权威文档，不重复粘贴已固化的大段历史。只有涉及服务器、数据库、生产服务或不可恢复动作时，才补充精确对象、操作前后状态和逐项回滚。时效性事实必须标注为快照，并要求 Luna 在动作前复核。

### 6.3 后台发送与等待

- Sol 确认 Luna 为空闲状态后才发送一条完整指令。
- 发送时按第 6.5 节选择推理档位，模型默认保持为 Luna。
- Sol 发送后优先进行一次长等待；只有 Luna 完成、请求确认、失败或用户发来新消息时才读取，不按固定间隔轮询。
- Luna 需要用户确认时，Sol 读取其请求，在 Sol 中向用户解释；不自行批准。
- Luna 完成后，Sol 直接读取最终结果及必要证据，不要求用户复制。
- 用户新消息会优先打断等待；Sol 根据新消息决定继续、调整或取消后续调度。

### 6.4 界面导航

- 默认后台调度，界面停留在 Sol。
- 用户说“让我看 Luna”“切到执行任务”时，Sol 才导航到 Luna。
- 导航不改变任务上下文、写入权或授权状态。
- 用户在 Luna 查看完成结果后，可以回到 Sol；Sol 仍以直接读取到的结果为审查依据。

### 6.5 模型与推理档位

| 任务 | 默认执行配置 | 升档条件 |
| --- | --- | --- |
| Git 状态、文件清单、文档整理、确定性格式检查 | Luna + Low | 发现无法解释的漂移或冲突 |
| 常规编码、测试、构建、依赖锁和明确故障修复 | Luna + Medium | 一次定位失败或出现跨层不确定性 |
| 复杂跨层诊断、迁移方案、生产切换前执行审查 | Luna + High，Sol 复核 | 仅在质量收益明确时使用 |
| 规划、授权边界和普通结果验收 | Sol + Medium | 数据库、生产切换、不可逆风险或架构重大变更时使用 High |

- 不默认使用 `xhigh`、`max` 或 Pro；只有普通配置无法可靠完成、且额外质量价值明确时才由用户决定升档。
- 同一阶段不要反复切换模型。机械检查失败时先看证据，不直接通过升档重跑全部流程。
- Terra 只作为复杂任务的可选成本折中，不为日常工作额外建立第三个长期任务，避免新增上下文和协调成本。

### 6.6 工具调用与证据压缩

- 相互独立的只读检查合并为一次工具调用或并行调用；有依赖关系、需要判断或需要授权的动作保持分步。
- 大型命令输出先在执行端统计、过滤和脱敏，只返回退出码、计数、文件名、错误分类和必要证据。
- 测试成功只报告命令类别、通过数、失败数和耗时；测试失败仅附第一个可操作错误及定位，不粘贴完整日志。
- Sol 不重复运行 Luna 已在干净提交快照中完成的全量测试；先核对提交、命令、退出码和保护边界，证据矛盾时才复跑。
- Luna 完成后由 Sol 直接读取最终结果；缺少字段时只追问缺失证据，不要求重新汇报整个阶段。

## 7. 用户授权规则

以下动作必须分别在 Sol 获得明确确认：

- 创建或切换 Git 分支。
- 暂存和创建提交。
- 推送 GitHub。
- 安装或升级依赖、拉取镜像、创建容器或卷。
- 创建、修改或删除服务器文件和目录。
- 停止、启动、重启、重载、启用或禁用服务。
- 向进程发送信号，修改 OpenClaw、cron、systemd 或网络配置。
- 数据库备份、恢复、迁移、写入或结构变更。
- 部署 staging。
- 切换生产流量或执行回滚。
- 删除临时环境、容器、卷、备份或发布目录。

一条授权只适用于提示词列出的阶段、对象和回滚。阶段完成后授权自动失效，不能推断下一阶段也已批准。

安全、预先列明且用户明确一并授权的应急回滚，可由 Luna 在触发条件满足时执行一次；超出该回滚必须重新确认。

## 8. Luna 阶段结果格式

Luna 每个阶段默认返回 7 个字段：

```text
结果：完成 / 停止 / 需要确认 / 失败后已回滚
基线：仅列出与交接不同的变化；无变化写“符合交接”
写入：实际动作与修改文件；无则写“无”
验收：测试、构建、Git、保护文件和敏感信息摘要
外部状态：服务器、服务、数据库和 OpenClaw；未接触写“未操作”
阻塞：无或第一个可操作问题
下一授权：精确下一动作；无则写“无”
```

只有发生外部写操作、回滚、异常漂移或测试失败时，才展开操作前后状态和最小错误证据。不把完整日志、秘密、真实持仓、数据库内容或私密连接信息写入结果。

## 9. 文档职责

- `00_LUNA_START_HERE.md`：只描述当前有效入口、当前阶段和下一任务。
- `LUNA_HANDOFF.md`：记录最近完成阶段、本地/GitHub/服务器快照、实际操作与下一确认门。
- `NN_LUNA_*.md`：记录一次阶段任务的完整范围、验证、停止条件和回滚。
- `docs/operations/CODEX_LUNA_ORCHESTRATION.md`：本文件，只记录长期不变的跨任务调度规则。
- `docs/operations/OPENCLAW_CODEX_COLLABORATION.md`：记录本地 Codex/Luna 与生产 OpenClaw 的职责边界。
- `docs/operations/RUNBOOK.md`：记录可长期复用的开发、发布、故障与回滚步骤。

PID、重启计数、临时端口占用和健康状态属于快照，应写入 `LUNA_HANDOFF.md` 或当前阶段文档，并标注日期；不要写成永久事实。

只有阶段、授权门、分支/SHA、服务控制权或阻塞发生实质变化时，才由当时唯一执行端同步 `00_LUNA_START_HERE.md`、`LUNA_HANDOFF.md` 和当前阶段执行令。纯只读复核且状态无变化时不改文档，只在结果中写“符合交接”。Sol 只在 Luna 空闲且写入权已经交回后补充长期规范。

## 10. Codex 重启、任务压缩与失联恢复

### 10.1 应用重启

1. Sol 重新列出任务，按项目、工作目录和标题识别现有 Luna。
2. 读取 Luna 最近状态，不直接重发上一条指令。
3. 读取 `00_LUNA_START_HERE.md`、`LUNA_HANDOFF.md` 和当前阶段执行令。
4. 只读核对 Git 和必要的外部状态。
5. 判断上一阶段是未开始、运行中、完成、失败还是需要确认。
6. 只有确认没有重复执行风险后才发送后续指令。

### 10.2 Luna 任务不可用

- 先重新列出任务和归档任务，确认不是隐藏、归档或主机暂不可用。
- 不根据旧任务摘要猜测执行是否完成。
- 若必须新建 Luna 任务，由用户明确提出创建；新任务从当前交接文档和实时只读核对开始。
- 旧任务恢复后，不让新旧两个 Luna 同时成为写入者。

### 10.3 长对话与上下文压缩

- 压缩后的任务仍以仓库交接文档和实时状态为准。
- 里程碑结束后可继续复用同一 Luna；不因对话变长自动新建任务。
- 当任务目标发生重大变化、旧上下文持续干扰或模型需要更换时，由用户决定是否创建新的执行任务。
- 新任务首条指令只提供当前目标、必读文档、基线、授权和停止条件，不复制旧聊天全文。
- 在阶段完成、提交形成或外部控制权改变等里程碑后更新交接；不在每条工具输出后制作新摘要。

## 11. 异常与重复防护

- Luna 已运行时，Sol 不发送第二条执行指令。
- 发送结果不确定时，先读取 Luna 最新消息，确认消息是否存在，再决定是否重试。
- Luna 汇报缺字段时，只发送补充证据请求，不让其重复整个阶段。
- Luna 命中停止条件时，不以“继续”“自行处理”等模糊提示绕过停止门。
- 用户取消或改变范围时，Sol 明确发送停止/调整指令；未确认 Luna 收到前，不让另一执行端接管。
- 任何共享状态与交接文档不一致时，以实时只读证据为准，并先修正交接后再继续。

## 12. 当前项目的长期默认流程

```text
用户在 Sol 提出目标或授权
        ↓
Sol 只读审查并生成单阶段执行包
        ↓
Sol 后台发送给现有 Luna，界面默认不切换
        ↓
Luna 独占写入权并执行、验证、更新交接
        ↓
Sol 等待并直接读取 Luna 最终结果
        ↓
Sol 只读复核，向用户汇报风险和下一确认门
        ↓
用户在 Sol 决定继续、调整、回滚或停止
```

生产侧任何时候仍遵循：明确 GitHub SHA、OpenClaw 控制边界、生产脏工作区停止规则、数据库备份门禁和逐项授权。

## 13. 立即停止条件

出现任一情况时，Sol 不再派发，Luna 停止写入：

- 无法唯一识别 Luna 任务或发现两个执行任务同时运行。
- Luna 正在运行时，用户又在 Luna 直接发送了范围不同的任务。
- Sol 与 Luna 同时修改共享工作区或服务器。
- 提示词没有明确授权范围、停止条件或回滚。
- Git 分支、SHA、差异文件、保护文件或服务器状态无法解释。
- OpenClaw 或其他控制端正在修改同一对象。
- 需要读取或输出秘密、真实持仓、数据库内容或完整日志才能继续。
- 外部写操作没有用户在 Sol 的明确确认。
- 结果无法证明已完成，但继续执行可能造成重复提交、重复部署或重复服务操作。
