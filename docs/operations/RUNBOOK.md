# my-funds 开发与运维手册

## 1. 日常开发

1. 在 `E:\myfund11111` 检查 Git 状态，并按 `CODEX_LUNA_ORCHESTRATION.md` 和 `OPENCLAW_CODEX_COLLABORATION.md` 登记阶段、执行端、任务范围、基础 SHA 和文件负责人。
2. 首次使用时执行 `E:\myfund11111\ops\Initialize-LocalDevelopment.ps1`。
3. 使用虚构数据、合成 MySQL 或仓库测试夹具开发，不导入生产数据。
4. 修改后执行 `ops/Invoke-LocalChecks.ps1 -RunPythonTests -BuildFrontend`。
5. 检查差异后提交到 GitHub，记录待部署提交 SHA。
6. 未明确要求部署时，不对服务器运行状态做变更。

长期默认由用户在 Sol 指挥任务中授权，Sol 后台调度现有 Luna 并等待结果，Luna 在执行阶段独占写入权。默认不切换任务窗口；GitHub 推送、staging、服务、数据库和生产切换分别确认。

## 2. 发布前检查

- 本地工作区没有意外文件或秘密。
- 目标提交已推送到 GitHub。
- 服务器磁盘空间、服务状态和仓库状态正常。
- 服务器仓库没有未提交改动。
- 数据库迁移已评估向前与回滚兼容性。
- 服务器端备份目录、容量和恢复命令已验证。
- 已记录当前线上提交 SHA，作为回滚目标。
- 已确认 OpenClaw 或另一执行端没有写入目标文件，自动拉取与重启机制的触发边界清楚。

## 3. 标准发布

1. 运行 `E:\myfund11111\ops\Test-ServerConnection.ps1` 做只读预检，并核对 OpenClaw、定时任务和服务重启策略。
2. 在服务器创建数据库与关键配置备份，备份不下载到本地。
3. 拉取目标提交并核对 SHA。
4. 按服务器实际方式构建前端和后端。
5. 执行经确认的数据库迁移。
6. 重启或滚动更新服务。
7. 验证健康接口、首页、静态资源、API 和关键业务流程。
8. 记录发布时间、提交 SHA、迁移版本和检查结果。

### 3.1 模型网关与分析模型

- backend 容器访问模型网关时必须使用容器网络中可达的网关地址；不能把容器自身的 `127.0.0.1` 当作其他容器的地址。
- `ANALYZER_PRIMARY_MODEL` 指定分析主模型，`ANALYZER_FALLBACK_MODELS` 指定英文逗号分隔的备用模型链；模型 ID 必须来自应用 NewAPI 的 `/v1/models`，不能直接复制 OpenClaw provider 前缀。
- 修改模型变量后，按标准发布流程重建 backend，并在隔离环境复核配置和回退链。
- 目录 GET 只能证明模型在网关目录中可见，不能证明模型推理质量、稳定性或业务结果。

## 4. 数据排查

- 优先查询表结构、行数、日期范围、聚合值和异常数量。
- 必须查看样本时，只返回脱敏后的最少字段和最少行数。
- 不输出 `.env`、连接串、API Key、邮件凭据或完整持仓。
- 复杂分析脚本在服务器运行，输出只保留结论、统计和错误定位信息。
- 数据修复先在事务或副本中验证，再确认写入生产库。

## 5. 故障处理

1. 停止继续发布和并发修改。
2. 记录故障时间、线上 SHA、服务状态和最近迁移版本。
3. 检查健康接口、容器或 systemd 状态及最小化日志。
4. 判断属于代码、配置、数据库、网络还是外部 API 故障。
5. 优先恢复服务，再进行根因修复。
6. 回滚后再次执行健康检查，并记录原因与后续措施。

## 6. 回滚原则

- 代码回滚到上一已知正常的明确 SHA。
- 数据库回滚只使用已验证方案；不可逆迁移优先采用向前修复。
- 配置回滚使用服务器端备份，不从聊天或本地临时文本恢复。
- 回滚完成后核对前端版本、后端版本、数据库版本和任务调度状态。
