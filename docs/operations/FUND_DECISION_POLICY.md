## 2. 决策时间和职责边界

- 目标分析时间：Asia/Shanghai 14:00，给用户预留人工操作时间。
- OpenClaw 负责交易日判断、定时触发和邮件投递。
- 应用代码负责数据质量、资金预算、冷却期和实际成交金额记录。
- 模型负责解释数据和生成候选观点，不得绕过代码门禁。
- 用户只在支付宝手工交易，系统不自动下单，也不因填写反馈自动修改真实持仓或现金。

实际 OpenClaw 定时从13:30改到14:00属于服务器任务变更，必须在对应代码发布后单独执行和验收；本地代码修改本身不代表服务器定时已改变。

## 3. 买入资金纪律

- 每日所有基金合计最多买入20元。
- 每月所有基金合计最多买入200元。
- 同一天最多给一只基金非零买入建议。
- 默认不在相邻交易日连续买入。
- 冷却期的严格例外只放宽“是否连续”的限制，不放宽每日20元和每月200元上限。
- 严格例外必须同时满足：整份报告数据完整、该基金数据质量良好、14:00属于对应市场实时盘中、实时信号为超跌、长期年化收益为正。
- 分析链路降级或数据质量不足时，所有非零金额归零，明确输出原因。

金额通过环境变量保留调整入口：

- `ADVISOR_DECISION_TIME`，默认 `14:00`。
- `DAILY_BUY_LIMIT_RMB`，默认 `20`。
- `MONTHLY_BUY_LIMIT_RMB`，默认 `200`。

## 4. 实际操作回填

用户在报告页面选择“照做、加仓、减仓、未操作或反向”，再填写支付宝实际成交的人民币绝对金额：

- 加仓保存为正数。
- 减仓保存为负数。
- 未操作保存为0。
- 照做或反向根据该报告的原建议确定方向。
- 回填只写入 `trade_execution`，用于计算当日和当月买入额度；不会自动修改持仓、现金或支付宝数据。

完成支付宝交易后，持仓本身仍应通过既有受控持仓更新入口同步，不能把“反馈记录”误当成“持仓已更新”。

## 5. 行情与净值限制

- 14:00展示的是跟踪指数方向，不是基金公司最终净值。
- QDII 基金存在时区、汇率和净值披露延迟，纳指两只基金在中国14:00不得标记为美股实时盘中。
- 交易所节假日仍由 OpenClaw 交易日门禁判断；应用中的周一至周五冷却计算不替代正式交易日历。
- 系统只能提高决策一致性和风险控制，不能保证盈利。

## 6. 每日使用步骤

1. 正常交易日14:00等待一封报告；不操作也应有0元摘要。
2. 先看数据质量和门禁原因，再看唯一非零金额建议。
3. 用户自行决定是否在支付宝操作，绝不把报告当成自动交易指令。
4. 操作后在报告页面填写实际动作和实际金额。
5. 再通过持仓更新入口同步成交后的真实持仓；遇到大额亏损时先停止新增投入，核对净值、份额和报告数据，不追涨杀跌。
